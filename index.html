00Aim

To state who Gezine actually is, what he has shipped across PlayStation and Switch, and precisely what his Switch 2 userland exploit does and does not mean for a console sitting on firmware 22.5.0 — separating what he said from what everyone repeated.

01Who he is

Gezine is a pseudonym. The GitHub account publishes no real name, no employer, no CV; the only geography on it is Seoul, South Korea, and the avatar is an anime illustration — a girl in a dark dress and a large hair ribbon, seen from behind against a blue sky. That combination is not unusual in console security: the work is legal-adjacent, the audience is anonymous, and a handle is the whole identity. Three-point-eight thousand followers, thirteen public repositories, sponsorships enabled.

What the profile reveals about method is more useful than any biography. Every project is a loader, not a jailbreak. The recurring shape is: find a trusted program that already reads data an attacker controls — a PS2 emulator's save file, a Blu-ray disc's Java menu, the YouTube app's cached assets, a physical game cartridge — and convert that read into code execution inside a sandbox the system has already decided to trust. Then package it so an ordinary person can run it: a backup file, a PKG, a payload sender on a TCP port.

The second tell is the credits. The README for his best-known release thanks roughly fifteen people by handle — a V8 researcher for CVE pointers, the psfree team for the kernel payload, someone who made the backup image, someone who provided elfldr. He is not a lone genius and does not present himself as one; the work sits inside a scene lineage and says so.

Console security is not one wall. It is a stack of rooms, each one permitted to talk to the next. Almost every item above is a door between two rooms that the system forgot to lock, because the room behind it was supposed to be safe. That sentence is the whole portfolio.

03The money, and what it implies

He joined HackerOne in April 2025. In August 2026 four PlayStation bug reports were resolved in a short window for $2,500 · $10,000 · $2,500 · $2,500 — $17,500 total. That is the honest frame for how he works: Sony pays, so Sony gets told first and quietly, and the results surface as a patched firmware rather than a release.

Nintendo runs no such programme. Switch work therefore gets published free, on a personal X account, with no coordination window — which is exactly why the Switch 2 thing arrived as a two-paragraph announcement instead of a write-up with a patch timeline. The asymmetry is not temperament. It is who is paying for silence.

04The Switch 2 exploit, in plain terms

1 — the problem he was solving

A userland exploit already existed "from day one." It was a save exploit: a specially-crafted save file, loaded by a game, corrupts something the game trusts. But a save exploit needs that save to physically arrive on your console, and the only sanctioned route for someone else's save is Nintendo Switch Online's transfer service, which insists on current firmware. So the exploit existed and was unreachable — for anyone who had not already updated past it. In his words: "even if a kexploit or some software-based privilege escalation is found, 99% of people can't use the save exploit." A jailbreak nobody can reach is a demo, not a tool.

2 — why he did not use the browser

Switch 2's WebKit carries ARM PAC — Pointer Authentication Code. Pointers in memory carry a cryptographic signature, and the CPU refuses to follow one that does not verify. Classic ROP attacks work by overwriting return addresses to stitch existing code fragments together; every step of that depends on forging a pointer. PAC does not make that hard, it makes it point at nothing. His explanation is one line: "Switch 2 WebKit has ARM PAC, which prevents ROP code execution. So I avoided it, as there was an easier way to exploit it." The browser is the first thing everyone suggests, and on this console it is the wrong door.

3 — what his exploit actually claims

Not WebKit. Not save data. "This one works without any restriction and works at all fw." He states it runs on both the original Switch and the Switch 2, and that it needs no network connection. He has not published which bug it uses, and there is no repository on his GitHub as of this writing. Reported independently by Notebookcheck and Nintendo Central, both quoting the same X thread — so the claim has three citations and one source.

4 — what "userland" rules out

Userland means the code runs inside a game's sandbox: you can do what that application can do, and nothing more. It is not custom firmware, it is not boot-level code, and it does not run copied games. Reaching the kernel is a second, separate exploit — a "kexploit" — and no public one exists for Switch 2. Both the exploit and its absence are true at once, which is the part the headlines flatten.

A proof that the door exists, with the key held up but not handed over. — the honest one-sentence summary of the 21 July disclosure

5 — the cartridge remark, and his own warning

He later clarified that people had conflated two things, and that there is separately an exploit based on a physical game cartridge — the point being you would not need to update firmware to use the eShop. He also warned against buying an Artemis-engine game specifically to exploit it: save exploits are a bad bet if Nintendo cuts online service. Both remarks point the same way as his earlier advice about SmileBASIC 4 — do not update your firmware to buy a game for an exploit.

05What this means for a console on 22.5.0

For the first time in this whole saga, a 22.5.0 machine is plausibly a target rather than a bystander. "All firmware" includes yours; that is the entire significance, and it is real.

  • Nothing to run. No download, no release, no mechanism. Even when released, userland without a kexploit yields homebrew inside one application's box.
  • The firmware is still the scarce asset. Updates are one-way and there is no downgrade path. An older build is worth something precisely because nobody can make more of it.
  • Value decays. An all-firmware userland bug announced in public is a bug Nintendo can hunt down and patch quietly. Expect it to be worth less in six months, not more.
  • Provenance is thin. One author, one thread, two aggregator articles. No independent test, no video, no second researcher confirming they reproduced it.

Which means the advice does not change: hold. Hold for a different reason now — not "no exploit exists," but "an exploit exists and is not in your hands."
